# unreal-mcp-playbook

An agent skill for building and polishing Unreal Engine games through the editor's MCP server, from Claude Code, Codex, Claude or any agent that reads `SKILL.md` skills.

> This is **not** an MCP server. Unreal Engine ships its own (the experimental Unreal MCP plugin). This is the playbook that teaches an agent to use it well.

Unreal's editor can expose almost everything (assets, levels, Blueprints, widgets, Play-In-Editor, scene capture, Python) as MCP tools. Connecting an agent is the easy part. Getting it to work like a careful developer, not a confident one, is what this skill is for:

- **Connect and confirm** the right editor and project, on any port, with or without native MCP support in your client.
- **Discover toolsets instead of guessing** tool names and parameters.
- **Use the right lever**: editor Python for inspection and batch work, the Blueprint DSL for logic, UMG tools for UI.
- **Back up, compile, save** at every step.
- **Verify like a player**: automated playthroughs from Python, viewport screenshots, frame captures turned into contact sheets and videos, and a checklist for reviewing them critically.
- **Build UI that holds together**: where UI logic can live, one visual system generated by script, correct texture and font scale, a checklist for every screen.
- **Design the game so it can be tested**: rules in one place, a reference model and solver outside the engine, replayed solutions and random comparison runs.
- **Avoid the traps** that cost hours (Static mobility, placed-actor overrides, negative `Fraction`, missing glyphs, editor freezes, fog that hides the game, packaging without a platform SDK).
- **Package a build** without blocking the editor, smoke-test it, and check the things that only break outside the editor.

It was distilled from building [Chain of Command](https://imadch.itch.io/), a seven-level puzzle game made in four days for the 2026 Epic AI MegaJam in UE 5.9, almost entirely through the MCP server.

## What's inside

```
unreal-mcp-playbook/
├── SKILL.md                    # the workflow the agent follows
├── references/
│   ├── connecting.md           # client configs, raw handshake, browser bridge for cloud agents
│   ├── toolsets.md             # toolsets and call shapes that worked, Python recipes
│   ├── blueprint-dsl.md        # reading, patching and writing Blueprint graphs as text
│   ├── ui.md                   # UMG: where logic lives, one visual system, scale, per-screen checklist
│   ├── verification.md         # testable design, PIE, playthroughs, screenshots, recordings, review checklist
│   ├── gotchas.md              # symptom → cause → fix table
│   └── packaging.md            # BuildCookRun from the editor, smoke test, checks
├── scripts/
│   ├── ue_mcp.py               # stdlib MCP client: probe, list, describe, call, run Python, screenshot
│   ├── contact_sheet.py        # frames → contact sheet, video (optionally resampled to even motion), before/after image
│   └── editor/record_frames.py # template recorder that runs inside the editor during Play-In-Editor
└── evals/                      # five test prompts used to check the skill
```

## Install

**Claude Code**: copy the folder to `~/.claude/skills/unreal-mcp-playbook/` (all projects) or `<project>/.claude/skills/unreal-mcp-playbook/` (one project).

**Codex**: put the folder where your Codex version looks for skills. Current docs describe `.agents/skills/` inside a repository; user-level skills have lived in `~/.codex/skills/`. See the [Codex skills docs](https://developers.openai.com/codex/skills).

**Claude (app)**: add the packaged `.skill` file from the releases page as a skill.

Or clone straight into place:

```bash
git clone https://github.com/ImadC9/unreal-mcp-playbook ~/.claude/skills/unreal-mcp-playbook
```

Then connect the editor's MCP server to your agent (see `references/connecting.md`), or just let the agent use `scripts/ue_mcp.py`:

```bash
python scripts/ue_mcp.py probe                     # is the editor answering?
UE_MCP_URL=http://127.0.0.1:8001/mcp python scripts/ue_mcp.py toolsets
python scripts/ue_mcp.py py -c "unreal.SystemLibrary.get_engine_version()"
python scripts/ue_mcp.py shot title_screen         # viewport capture during PIE
```

Requirements: Unreal Engine with the **Unreal MCP** plugin (`ModelContextProtocol`, experimental) and **All Toolsets** enabled ([Epic docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-mcp-in-unreal-editor); tested on 5.9), Python 3.8+ for the scripts, Pillow for `contact_sheet.py`, ffmpeg for video output.

## Example requests

- "Check the Unreal MCP is working and tell me what's in my level."
- "Build a greybox of this game design doc in Unreal with cubes, playable end to end."
- "The dust particles I added don't show up in PIE. Find out why."
- "Polish the HUD; it looks janky. Make sure it actually looks good in game."
- "Run every level's solution and make sure they still win after this change."
- "Package a Windows build under 1 GB and check it launches."
- "Record a 6-second clip of level 3 for the tutorial card."

## How it was tested

Five realistic requests were given to separate agents with and without the skill and graded against fixed checks (see `evals/`). With the skill: 29 of 29 checks. Without: 20 of 29. The tests are written deliverables (scripts and plans); the skill's content comes from real sessions against UE 5.9, but the test runs themselves had no live editor.

## Notes

- Tool names and parameters vary between engine versions and enabled plugins. The skill tells the agent to describe tools before using them; the names in `references/` are from UE 5.9.
- The agent changes your project. The skill makes it back up before structural changes, but use source control too.
